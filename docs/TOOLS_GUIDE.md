# Руководство по инструментам (tools/) PSU48

Скрипты в `tools/` генерируют и проверяют проект PSU48 (KiCad 10) "из текста":
схема, библиотека, плата, размещение и (экспериментально) трассировка.
Часть кода универсальна и пригодна для других независимых проектов; часть —
жёстко привязана к конфигурации `tools/sch_data.py`. Ниже — реестр, порядок
работы, способ переноса на новый проект и ограничения.

---

## 1. Окружение

- Windows, KiCad **10.0** (`C:/Program Files/KiCad/10.0`).
- Python берётся из дистрибутива KiCad:
  `"C:/Program Files/KiCad/10.0/bin/python.exe"` (свой системный Python не требуется).
- Все скрипты запускаются из каталога `tools/` (они импортируют друг друга через
  относительные имена).
- CLI KiCad: `"C:/Program Files/KiCad/10.0/bin/kicad-cli.exe"`.
- Единица хранения данных — **S-выражение** (S-expr). Парсинг/сериализация
  полностью вынесены в `sexp.py`.

## 2. Реестр скриптов

| Файл | Роль | Переиспользуемость |
|------|------|--------------------|
| `sexp.py` | Парсер/сериализатор S-expr (KiCad-совместимый), helpers `find/findall/unq/Q/num` | Полностью универсален |
| `kilib.py` | Чтение `.kicad_sym`/`.pretty/*.kicad_mod`, геометрия выводов, встраивание symbol в `lib_symbols` | Универсален (слой библиотек KiCad) |
| `sch_data.py` | **Конфигурация проекта**: листы, элементы, сети, клеммы питания, отверстия | Только psu48 (заменить целиком) |
| `schgen.py` | Генератор `.kicad_sch` (корень + листы) из `sch_data`; пишет `.kicad_pro` | Ядро универсально, питается конфигом |
| `verify.py` | Экспорт netlist (`kicad-cli sch export netlist`) + сверка с `sch_data` | Универсален (нужен конфиг) |

| `router.py` | Экспериментальная автотрассировка (2 слоя, A*, треки/виа) — **β** | Ядро универсально; стили шин/порядок — конфиг |

## 3. Порядок работы (workflow)

Оптимальный порядок для нового проекта:

1. **Библиотеки** — `mklib.py` (если используются свои символы/корпуса).
2. **Схема** — `schgen.py`: пишет `kicad/<project>.kicad_sch`,
   `kicad/<sheet>.kicad_sch`, `kicad/<project>.kicad_pro`.
3. **Проверка схемы** — `verify.py` (сверка pin↔net против конфига) и
   `kicad-cli sch erc <root>.kicad_sch -o out.rpt`.
4. **Контроль корпусов** — `qa.py`.
5. **Плата + размещение** — `pcbgen.py`: пишет `kicad/<project>.kicad_pcb`.
6. **DRC посадочных** — `kicad-cli pcb drc ... --severity-all`.
7. **Трассировка (экспериментально)** — `router.py` (дописывает треки/виа в ту же плату).
8. **Финальный DRC**, затем вывод Gerber/Drill/BOM/CPL/PDF через `kicad-cli`.

Типовые команды (из `tools/`):

```bash
PY="C:/Program Files/KiCad/10.0/bin/python.exe"
"$PY" mklib.py
"$PY" schgen.py
"$PY" verify.py
"$PY" qa.py
"$PY" pcbgen.py
"$PY" router.py            # β
CLI="C:/Program Files/KiCad/10.0/bin/kicad-cli.exe"
"$CLI" pcb drc ../kicad/psu48.kicad_pcb -o C:/tmp/pcbdrc.rpt --severity-all
```

## 4. Адаптация под новый проект

Минимально заменяется конфиг `sch_data.py`; имя проекта и параметры
разбросаны в заголовках скриптов.

### 4.1 `sch_data.py`
- `PROJECT`, `ROOT_TITLE`, `REV`, `DATE` — имя и шапка.
- `POWER_TERMS` — глобальные (клеммные) сети.
- `SHEETS` — список листов с элементами `{"id", "title", "entries": [{ref,
  fp, val, nets, at, bb, pinmap, ...}]}`. Это **расширяемая спецификация**
  схемы: по ней schgen рисует лист, verify сверяет, pcbgen ставит корпуса.
- `ROOT_HOLES` — монтажные отверстия.
- Геометрия размещения (`X0/Y0/COL_GAP/...`) — разметка листа.

### 4.2 `pcbgen.py`
- `BOARD_W`, `BOARD_H` — габариты платы.
- `PREFER`, `GROUP_ANCHOR`, `REGION_BOARD`, `HOLE_POS`, `MARGIN`, `PACK_STEP` —
  стратегия размещения (якоря структур/листов, допуски).
- `fp_path()` — откуда брать `.kicad_mod` (проектная `psu48.pretty` или
  стандартная библиотека KiCad).
- `net_name()` — правила "локальная/глобальная" сеть в имени платы.

### 4.3 `router.py`
- `net_style(net)` — ширина/класс по имени сети (OUT/HV/PWR/SIG).
- Порядок трассировки `route_key()` (класс → число падов).
- Параметры через env (см. ниже).

## 5. Ограничения

### Общие
- Скрипты рассчитаны на одну плату/один уровень иерархии схемы; символы
  только из `.kicad_sym` (KiCad 10 S-expr), не Symbol-Library-Table v7.
- Никакой GUI-проверки: корректность подтверждается только `kicad-cli
  drc/erc` + `verify.py`.
- Формат вывода заточен под **KiCad 10** (см. §6).

### Роутер (`router.py`) — экспериментальный
- Сетка трассировки — **0.2 мм**; минимальный эффективный зазор —
  `ROUTE_CL≥0.2`. Из-за квантования невозможно провести трассу к выводу
  SOIC-шага 1.27 мм с чистым DRC — зазор между соседними контактными
  площадками закрывается кольцами запаса. Сигнальные сети в плотных
  кластерах могут оставаться неразведёнными.
- Только **2 сигнальных слоя**, A* с 4-соседними переходами, виа 1.2/0.6 мм.
- Многослойная связность падает при большом числе падов у сети (манхэттенский
  поиск по сетке — не промышленный роутер; для высокой заполненности нужен
  fanout/эскейп-роутинг).
- Ядро **не проверяет** реальный DRC сам; контроль — внешний `kicad-cli pcb drc`.
- Режимы через переменные окружения:
  - `PSU_STEP` — шаг сетки, мм (по умолчанию 0.2; 0.1 — заметно медленнее);
  - `PSU_SIGW` — ширина сигнальных трасс (0.3);
  - `PSU_CL` — зазор трассировки (0.25);
  - `PSU_RCAP` — множитель узости колец запаса (0..1; 0 открывает каналы и
    может нарушать DRC).
- Текущее состояние: большинство силовых сетей проводятся; сигнальные
  сети между выводами мелких корпусов — предмет доработки.

### `pcbgen.py`
- Размещение строится структурно (функциональные группы листов), а не
  по соединениям; auto-оптимизатора нет.
- Сети "склеиваются" по правилам `net_sheets_map()`: локальные сети листа
  получают префикс `Лист/Сеть` — решение специфично для иерархии проекта.

### `schgen.py`
- Переиспользуемо как движок "S-expr → лист", но разметка листа
  (`PAPER_LIMITS`, перенос при `Overflow`) отражает стиль psu48.

## 6. Особенности KiCad 10, зафиксированные в проекте

Эти детали важны при генерации любых файлов для KiCad 10:

- **Треки и виа** в `.kicad_pcb` используют атрибут `(uuid "...")`, а **не**
  `(tstamp ...)` — иначе "Failed to load board: Expecting ')'".
- Внутри `(segment ...)`/`(via ...)` сеть пишется **только кодом** без имени:
  `(net 4)`, а не `(net 4 "+48V")` (в узлах сетей платы — наоборот, и код, и имя).
- Порядок критичных узлов платы: `(kicad_pcb (version) (generator)
  (general) (paper) (title_block) (layers ...) (setup ...) (net ...)`*
  затем корпуса, затем треки/виа, в конце `(embedded_fonts no)`.
- Чисел с ведущими пробелами не допускается; числа печатаются через
  `sexp.num()` (максимум 6 знаков, без хвостовых нулей).
- Кодировка файлов — UTF-8, переводы строк `\n` (не `\r\n`).
- `sexp.py` сохраняет точный исходный текст атомов: строки остаются в
  кавычках (`Raw`), поэтому round-trip идентичен исходнику.

## 7. Как понять и изменить внутреннюю модель

- **Узел** в `sexp.py` — обычный Python-список: `["kicad_pcb",
  ["layers", ...]]`. `dumps()` сам добавляет скобки и отступы.
- `Raw("...")` — "сырое" значение (например, `'"F.Cu"'`), его нельзя
  редактировать как строку Python.
- Порядок и обработку данных смотри: `sch_data.py` (спека) →
  `schgen.py`/`verify.py` (схема) → `pcbgen.py` (плата) → `router.py`
  (трассы). Каждый следующий потребляет предыдущий через общий конфиг.

## 8. Итог для переноса

| Что нужно | Где править |
|-----------|------------|
| Имя проекта / шапка | `sch_data.py` |
| Список листов и элементов | `sch_data.py` (секции `SHEETS`) |
| Глобальные сети | `sch_data.py` (`POWER_TERMS`) |
| Монтажные отверстия | `sch_data.py` (`ROOT_HOLES`) + `pcbgen.HOLE_POS` |
| Габариты платы | `pcbgen.BOARD_W/BOARD_H` |
| Стратегия размещения | `pcbgen.PREFER/GROUP_ANCHOR/REGION_BOARD` |
| Ширины/приоритеты трасс | `router.net_style()/route_key()` |
| Зажим точности роутера | env `PSU_STEP/PSU_SIGW/PSU_CL/PSU_RCAP` |

Универсальные блоки (`sexp.py`, `kilib.py`, ядро `schgen/verify/pcbgen/router`)
берутся без изменений; проектная спецификация целиком сосредоточена в
`sch_data.py` + нескольких таблицах констант в заголовках генераторов.
